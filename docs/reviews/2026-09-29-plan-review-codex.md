## 1. Strategy

**The M1–M2 gate does not yet support the intended X story.** M2 ends with calibration labels, a taxonomy, and cost projections. Held-out quality, reviewed findings, and real site data are deferred, while six parallel lanes build a seven-page site and release machinery. A calibration threshold chosen to reach 0.90 recall is especially easy to mistake for a measured result. Keep the pilot report explicitly exploratory. Move held-out evaluation and a small, human-reviewed finding exercise ahead of the full site build; publish a null result if no candidate clears a written evidence bar. [Master scope and Wave 2](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:17), [master Task 2.2](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:870), [L6 goal](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L6-site.md:5).

**“Recurring unmet problems” needs a decision rule.** The spec asks for independent evidence and contradictions, but sets no minimum thread or month spread, no reviewer decision record, and no rule for resolved cases. The M2 taxonomy sample contains only Jev-positive comments, so it can miss whole categories of false negatives. Define a finding acceptance rubric before reviewing candidates, audit some predicted negatives, and call the outputs *startup hypotheses*, not evidence of demand. [Spec §§1, 6](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/specs/2026-09-29-jev-opportunity-atlas-design.md:13), [master Task 2.3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:877).

## 2. Engineering

**L7 cannot run both question sets under L3’s stated manifest rule.** L3 writes one `question set label` to `run_manifest.json` and raises when a later call differs. L7 runs `screen@0` and then `deep@0` in the same run. Its end-to-end test should therefore fail on the deep pass. Define a run manifest containing an immutable list of question sets and hashes, plus a separate completion key for `(run, comment, question set)`. [L3 Task 3.7, Step 3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L3-inference.md:460), [L7 Task 7.3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L7-pilot.md:58).

**Resume is neither charge-safe nor answer-safe as specified.** L3 records ledger rows only after `evaluate` returns, then marks a comment done while answers may remain in a 500-item buffer. A crash can produce an unrecorded paid attempt, repeat that call, or leave a “done” item without answers. Write and sync an attempt-start record before dispatch; persist attempts and answer parts atomically; mark completion only after verifying the answers. Treat a crash after dispatch as an unknown charge until reconciled. Add crash-point tests. [L3 Tasks 3.4 and 3.7](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L3-inference.md:330).

**The $1 guard is a per-process estimate, not a project cap.** One reservation covers a logical call, but the client can make four network attempts. Actual usage may exceed the token estimate; the 8,000-token unknown charge is an assumption, not a provider-enforced maximum. Two runs or processes have separate guards, so each can spend $1. The plan also assumes most 4xx responses cost zero without billing evidence. Use a single locked pilot budget across runs, reserve for each attempt, persist reservations, stop on uncertain exposure, and describe the cap as an estimated dispatch limit unless TypeSafe supplies a hard billing limit. [L3 Tasks 3.3–3.5](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L3-inference.md:275), [L7 Task 7.3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L7-pilot.md:60).

**Sampling and intervals need a design fix.** L2 allows zero allocations in nonempty strata, yet later treats the sample as representing the whole eligible frame. Its bootstrap resamples observed threads separately within comment strata, although one thread can contribute comments to several months, and it omits the finite-population design. Ensure every reported stratum has positive inclusion probability, state which strata are uncovered, and validate interval coverage with simulated clustered populations before using those intervals publicly. [L2 Tasks 2.2–2.3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L2-sampling.md:132).

**The quality API cannot produce the spec’s population metrics.** The spec calls for a held-out set sampled by Jev prediction with known selection rates. L4’s queue is uniform, its saved queue has IDs and seed but no conditional selection probabilities, and `evaluate` passes no declared weights. Reliability bins and choice accuracy are unweighted too. Freeze the prediction strata and selection rates in a held-out manifest; combine breadth inclusion and held-out selection probabilities for precision, recall, baseline, and calibration; bootstrap the full two-stage design. Keep calibration results out of reported quality. [Spec §7](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/specs/2026-09-29-jev-opportunity-atlas-design.md:184), [L4 Tasks 4.2–4.6](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L4-evaluation.md:64).

**Snapshot verification does not prove its frame or resource claims.** L1 drops records without an `item` in Pass 1, but its coverage contract does not explicitly reconcile null and failed IDs to every scanned ID. It builds Python parent maps for millions of items, materializes 200,000-row text batches, and has no snapshot-stage disk guard despite 14 GiB free. Fixed row-group size alone does not establish byte-identical Parquet across environments. Add an ID-state reconciliation test, peak-memory and scratch-disk checks, streaming writers, pinned serialization versions, and a logical-content checksum alongside file hashes. The existing acquisition guard covers acquisition, not this build. [L1 Task 1.5](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L1-snapshot.md:237), [acquisition disk guard](/Users/hansel/conductor/repos/jev-opportunity-atlas/src/atlas/sources/acquire.py:74).

## 3. Security and privacy

**The proposed pre-commit scan can miss a staged secret and can print another secret.** `scan_cli --staged` obtains staged names but scans working-tree files. A secret staged and then removed locally passes that Python check; gitleaks is optional in the hook, and CI runs only after a public push. `_redact` replaces one match but retains the rest of the line, so a second key on the same line can appear in the error preview. Scan staged blob bytes, require the scanner before push, and print rule, path, and line only. Add two-secrets-on-one-line and staged-versus-working-tree tests. [Master Tasks 0.4–0.5](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:488), [master Task 0.9](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:812).

**The export allowlist directly conflicts with the no-bulk-text rule.** M2 saves the 300 comments given to Claude in `taxonomy/v0/provenance.json`; L5 exports `taxonomy/**/*.json` without stripping. That can publish HN text and possibly usernames. The scanner searches for secret patterns, not all HN content or PII, and reading compressed Parquet as text is no substitute for checking decoded columns. Export a text-free taxonomy provenance summary, validate every decoded output schema and string field, and keep source comments local. Also constrain a real-key client to the intended HTTPS host; `TYPESAFE_BASE_URL` currently accepts any destination for a bearer key. [Master Task 2.3](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:877), [L5 Task 5.1](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L5-publication.md:82), [L3 Task 3.1](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L3-inference.md:97).

## 4. Developer experience and site UX

**A stranger cannot audit the promised metrics from the proposed release.** L5 exports answers and summary evaluation JSON, but omits the selected-ID sample Parquet and raw blind labels. Its claims checker accepts an arbitrary scalar SQL result; its example uses `avg(firsthand)`, which is wrong for a disproportionate sample. Ship text-free sample and label records with selection probabilities, rubric and question files, and a versioned aggregation command. Have claims checks verify denominator, lane, run, question version, weighting, and interval as well as the scalar. [L5 Tasks 5.1 and 5.4](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L5-publication.md:82), [spec §9](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/specs/2026-09-29-jev-opportunity-atlas-design.md:258).

**The frozen site table does not support the planned Evidence page.** Its `evidence` row lacks TypeSafe confidence, choice probabilities, sample weight, and original text hash, while the page promises probabilities, confidence, weighted drilldown, and support-sentence highlighting. Live HN text may have changed since classification; the page needs a `changed`, `deleted`, or `unavailable` state and must suppress original-answer highlighting on a hash mismatch. Add the required fields to the site contract before L6 starts. [L6 table contract and Task 6.4](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L6-site.md:23).

**The runbook and deployment defaults invite mistakes.** Master Task 2.1 omits `--snapshot`, required by L7; Task 2.2 omits it for L4’s `label` command. L6 silently uses fixtures when `ATLAS_SITE_DATA` is absent, while the Pages workflow can be manually dispatched. A build test that merely finds the words “FICTIONAL DATA” in JavaScript does not establish the deployed mode. Make production builds fail without a verified real-data manifest; retain an explicit preview command for fixtures. Test the documented CLI commands and inspect the built `meta.mode`. [Master Tasks 2.1–2.2](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-00-master-plan.md:858), [L7 Task 7.4](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L7-pilot.md:65), [L6 Tasks 6.2 and 6.5](/Users/hansel/conductor/repos/jev-opportunity-atlas/docs/superpowers/plans/2026-09-29-L6-site.md:69).
